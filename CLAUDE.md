## Commands

```bash
bun run dev                      # Turbopack dev server
bun run typecheck                # next typegen && tsc --noEmit
bun run lint                     # eslint
bun run test                     # vitest run
bun run build                    # production build

bun run test question-state      # one file, by path substring
bun run test -t "ignores ordinary messages"   # one test, by name
```

CI runs typecheck, lint, test and build. All four should be green before committing.

**Do not run Prettier.** There is no Prettier config, and the repo is written at ~100 columns against Prettier's default 80 — `prettier --write` reformats whole files and buries a real change in hundreds of lines of churn. `prettier --check` reports every file in the repo, including untouched ones; that is expected, not a signal.

## Test harness constraints

- `vitest.config.ts` matches **`tests/**/*.test.ts` only**. A `.tsx` test is silently not run. To test a React component, use `createElement` + `renderToStaticMarkup` from a `.ts` file (see `tests/markdown-highlight.test.ts`).
- `environment: "node"` — **there is no DOM and no browser.** Anything depending on layout, measurement, `ResizeObserver` or a real render cannot be unit-tested here. Extract the pure logic and test that; say plainly what remains unverified.
- `server-only` is aliased to a stub, and `mermaid` is inlined into Vite's transform so `vi.mock` can reach it.

## React Compiler lint rules are enforced

`eslint-config-next` turns these on, and they fail the build. Fix the cause rather than suppressing — the established patterns in this repo:

- **`react-hooks/purity`** — no `Date.now()`/`Math.random()` during render. Use `useState(() => Date.now())`.
- **`react-hooks/set-state-in-effect`** — don't clear state synchronously in an effect. Stamp state with what produced it and derive staleness during render: `const current = rendered?.key === props.key ? rendered : null`. Used in `flow-view.tsx` and `use-chat-pages.ts`.
- **`react-hooks/immutability`** — don't reassign a `let` accumulator inside `useMemo`; compare against the previous element instead (`all-chats-page.tsx`).

## The tool layer

`src/lib/tools/*` are pure functions taking args and returning a Zod-validated spec; `src/lib/tools/index.ts` wraps each in the AI SDK's `tool()`. Two contracts that aren't obvious from one file:

- **Every render tool needs `toModelOutput`.** Without it the SDK feeds the tool's full return value back into the prompt — so the model's own HTML/table/chart spec is replayed as a tool result on every subsequent turn, doubling its token cost and often causing the model to *also* write a markdown copy of the widget. Use the `ack()` helper: a one-line description, never the payload. `parse_data` shipped without this and produced every table twice.
- **Per-user state arrives as an injected port** (`MemoryStore`, `SkillStore`), never imported. That is why no tool touches the database and every tool has a test.

## Streaming performance is a design constraint

The transcript re-renders on **every streamed token**. `message-list.tsx` memoizes `UserMessage`/`AssistantMessage` so only the message being streamed does work; the AI SDK replaces message objects rather than mutating them, so shallow comparison is enough. Anything added to the render path is paid per token:

- Keep plugin arrays and options at module scope — an inline `[remarkGfm]` rebuilds the whole unified pipeline per token (`markdown.tsx`).
- Callbacks passed into the transcript must be stable; see `messagesRef` in `chat.tsx`.

## Client/server boundary

`src/lib/db/*` is `server-only`. Importing it from a client component drags the Postgres driver into the browser bundle, so shared constants are **deliberately duplicated** rather than imported — `CHATS_PAGE_SIZE` in `queries.ts` and `PAGE_SIZE` in `chats-provider.tsx` must be kept in step by hand.

Every query in `src/lib/db/queries.ts` scopes by `userId`. A query that forgets is an authorization bug.

## Styling

Use the tokens in `src/app/globals.css`, not raw Tailwind palette classes.

The type scale is four named steps — pick the **role**, not a pixel size:

| Class | Size | Use |
|---|---|---|
| `text-prose` | 15px | assistant answers, user messages — the only step meant for reading at length |
| `text-ui` | 14px | interactive text, inputs, primary buttons |
| `text-dense` | 13px | chrome, lists, widget headers |
| `text-micro` | 11px | chips, hints, timestamps |

`text-lg`/`text-xl` remain for page titles. Don't introduce a fifth size — the scale exists because there used to be ten.

Tool output is wrapped in `WidgetShell` (bordered card, icon, title). The exception is `html-view.tsx`, which deliberately has no chrome: a generated artifact is the answer, not an attachment to it.

## Database

Schema changes go `db:generate` → commit the SQL → `db:migrate`. **Never run `db:push` against a database with real data** — it diffs and drops. `DATABASE_URL` in `.env.local` may point at production; check before running anything that writes.

## Privacy invariants

- The model API key lives in `localStorage` only, is sent per-request as `x-model-key`, and is never written to the server or database.
- A private chat (`/private`) is fully ephemeral: no `chat` row, no `message` rows, no title, no memory read or written. The `private` flag is client-supplied and safe because it can only ever *remove* capability — see the comment block in `src/app/api/chat/route.ts`.
